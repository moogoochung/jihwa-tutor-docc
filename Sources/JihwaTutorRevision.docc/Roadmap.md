# 전체 구성과 개편 방향

단계마다 실행 가능한 결과가 남도록 입력부터 실기기 연결까지의 순서를 정리합니다.

## Overview

### 문서가 약속할 결과

제목은 **「지화 튜터 프로토타입 만들기」**로 바꿉니다. 부제는 **「가짜 관절 입력에서 채점·교정 문장, Vision Pro 손 추적 연결까지」**로 제안합니다.

독자는 시뮬레이터에서 손 입력, 특징 추출, 기준 포즈 등록, 채점과 교정의 연결 구조를 구현합니다. 실제 지화를 정확하게 가르칠 수 있는지는 표준 손 모양과 실측 데이터를 별도로 검증해야 합니다. 자모 40개를 코드에 등록한 사실과 40개를 정확하게 구분한다는 결과를 구분합니다.

기존의 가짜 입력부터 시작하는 접근, 준비 지식 안내, 단계별 체크포인트는 유지합니다. 가장 큰 변경은 **각 단계의 코드·실행 화면·성공 조건을 같은 프로젝트 버전에 맞추는 것**입니다.

### 단계별 개편안

아래 파일 이름은 제안하는 새 구조입니다. 현재 소스에 이미 모두 있다는 뜻은 아닙니다. 각 단계는 앞 단계까지의 파일만 사용하며, 새 파일은 본문에서 정의한 뒤 사용합니다.

| 단계와 새 제목 | 이번 단계에서 추가·수정할 것 | 단계 종료 시 확인할 결과 |
| --- | --- | --- |
| 0. 프로젝트와 첫 창 만들기 | `JihwaTutorApp`, 최소 `TutorView` | 모델과 손 추적 없이 제목이 있는 창이 실행된다. |
| 1. 가짜 관절 입력 재생하기 | `HandFrame`, `HandFeed`, `MockHandFeed`, 디버그 화면 | 관절 수·입력 시각이 갱신되고 정지 후 다시 시작할 수 있다. |
| 2. 관절 좌표를 22개 특징으로 바꾸기 | `PoseFeature`, `FeatureExtractor`, 특징 표시 화면 | 굽힘 15개·벌림 4개·법선 3개를 표시한다. |
| 3. 기준 포즈를 기록하고 저장하기 | `Jamo`의 첫 항목, `ReferencePose`, `ReferenceLibrary`, `RecorderModel`, `RecordingView` | 기록 → 평균 → 등록 → 저장·복원을 수행하고 데이터 출처를 표시한다. |
| 4. 오차를 채점하고 교정하기 | `PoseMatcher`, `PoseMatch`, `Coach`, `Stabilizer`, `TutorModel`, 기존 디버그 화면 수정 | 굽힘·벌림 오차 방향에 맞는 문장을 내고, 판정 실패 이유를 표시한다. |
| 5. 자모 40개와 비교 화면으로 확장하기 | `Jamo` 확장, 데모 기준표, 선택·판정·오차 화면 | 40개 항목을 선택하며 기준 상태와 혼동 후보를 확인한다. |
| 6. 실제 손 추적과 오차 표시 연결하기 | `HandTrackingFeed`, `PracticeSpace`, `GuideOverlay`, 권한·세션 상태 | 실기기 입력을 같은 계산 경로에 연결하고, 추적 중단·재시작을 처리한다. |

권장 데이터 흐름:

```text
MockHandFeed ────────┐
                    ├─ HandFrame → FeatureExtractor → PoseFeature
HandTrackingFeed ────┘                                  │
                                        ┌──────────────┴─────────────┐
                                        ↓                            ↓
                               기록·기준 포즈 등록             채점 → 교정·화면
```

`MockHandFeed`는 자체 합성 관절 데이터만 재생합니다. 나중에 만드는 `ReferenceLibrary`를 읽어서 입력을 만들지 않습니다. 그래야 기준값을 바꿨을 때 가짜 입력도 함께 바뀌어 시험 결과를 왜곡하는 일을 피할 수 있습니다. 기준 포즈는 채점에 사용하는 별도 데이터로 관리합니다.

예상 시간은 기존 값을 그대로 옮기지 않습니다. 개편된 각 단계를 실제로 따라 만든 뒤, 설치·실기기 연결 시간이 포함되는지와 함께 다시 기재합니다. Swift 행 수보다 완료 결과를 먼저 보여 줍니다.
