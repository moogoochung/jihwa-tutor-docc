# 구현 우선순위와 완료 기준

기능을 수정한 뒤 무엇을 확인해야 하는지 우선순위별로 정리합니다.

## Overview

| 우선순위 | 변경 | 완료를 확인하는 방법 |
| --- | --- | --- |
| 1 | 단계별 프로젝트 분리 | 각 단계의 제공 파일만으로 빌드·실행한다. 해당 버전에서 본문 스크린샷을 다시 만든다. |
| 1 | 기록 UI와 등록·저장 연결 | UI로 새 기준을 등록하면 판정 기준이 바뀌고, 재실행 후 복원된다. 데모 출처는 유지된다. |
| 1 | 수향 좌표계 수정 | 동일 합성 포즈의 전체 회전 시 굽힘·벌림은 유지되고 법선이 예상 방향으로 바뀐다. |
| 1 | 스트림 재시작 | 시작 → 정지 → 시작을 반복해도 새 입력이 도착한다. 종료된 스트림을 재사용하지 않는다. |
| 1 | 교정 방향과 실패 이유 일치 | 벌림 양·음 오차를 각각 확인하고, 수향 가중치나 복합 오차로 실패해도 이유가 표시된다. |
| 2 | 허용 오차 일원화 | 한 관절의 저장 허용 오차를 바꾸면 판정·문장·그래프가 같은 값을 사용한다. |
| 2 | 3D 설명과 구현 일치 | 임시 표시에는 정답 손이라는 이름을 쓰지 않는다. 정답 뼈대 기능은 구현 후 별도 검증한다. |
| 2 | 기준 상태와 혼동 후보 갱신 | 실측/데모/검토 상태를 구분하고, 기준과 설정 변경 시 후보 목록을 갱신한다. |

스트림은 시작마다 새 스트림과 continuation을 만들고 소비자가 그 새 스트림을 받도록 설계합니다. 이전 생산·소비 작업은 종료한 뒤 교체합니다. 중복 시작이나 빠른 시작·정지에서도 오래된 작업이 새 세션 상태를 덮어쓰지 않는지 확인합니다. 단순히 `let`을 `var`로 바꾸는 것으로 완료했다고 보지 않습니다.
